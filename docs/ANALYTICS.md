# GA4 の導入と確認

このアプリ専用のGA4プロパティを使います。管理先は `apps@entertainment.co.jp` です。測定IDは公開情報であり、APIキーやサービスアカウントの秘密鍵はブラウザーに置きません。

## 設定

- `./analytics-config.js` の `measurementId` に、このアプリ専用の正式なWebストリーム測定IDを設定します。未設定なら外部通信も計測UIも動きません。
- `productionHosts` は確認済みの本番ホストだけを完全一致で設定します。空配列、未登録ホスト、HTTP、localhost、プレビュー環境では計測しません。
- GA4管理画面の当該Webストリームで拡張計測機能をオフにします。ブラウザー履歴・フォーム・クリックの自動収集による二重送信や、OAuthクエリ・入力内容の送信を避けるためです。
- ページ末尾の「アクセス解析の設定」で許可した場合のみGoogleタグを読み込みます。拒否時と未選択時はGoogleへ送信しません。許可の取り消し時は計測を停止して再読込します。同じアプリを開いた別タブでの選択変更も同期し、許可の取り消しを反映します。選択はこのアプリ専用のlocalStorageキーに保存し、保存不能な環境では当該ページ中だけ有効です。
- 広告ストレージ、広告ユーザーデータ、広告パーソナライズは拒否のままです。広告SDK・広告サービスは追加していません。

## イベントとデータ

`artists_extracted`、`playlist_generated`、`playlist_saved`、`spotify_connected`。操作の成立した地点を計測します。ただし `manual_refresh` は更新操作の開始を表します。

`page_view` は各HTML表示につき1回です。固定ページタイトルと設定にある正規パスだけを送り、URLクエリ・ハッシュ・参照元パスは送りません。イベントの任意パラメーターを受け付けず、ファイル名・CSV内容・自由入力・Spotify認証コード・メールアドレス・パスワード・エラー本文は含めません。

既存のGoogleタグ/GTMを検出した場合、追加のタグを初期化しません。既存のタグ管理を採用する場合は、どちらで同意とイベントを管理するか統合してから有効にします。

## 検証と公開

`node --test scripts/analytics.test.mjs` と `git diff --check` を実行します。テストは外部通信せず、未設定・未知ホスト・開発ホスト・同意前の停止、許可後の単一初期化、安全なイベント、拒否を検証します。

公開前にプライバシー表示と同意UIを確認します。本番公開後、未同意時はGoogleへのリクエストがなく、許可後に `gtag/js` とGA4収集が発生することをブラウザーで確認し、GA4リアルタイム/DebugViewで当該専用プロパティへの受信を確認します。許可の取り消しも確認します。コード追加、サービス設定、公開、実イベント受信は別々に記録してください。このテストの合格はGA4側の受信を証明しません。
